WebGL / Canvas2D parity test

Each stimulus can render either on the CPU (Canvas 2D) or on the GPU (WebGL 2). This test opens each stimulus in ?parity=1 mode: it renders one representative frame both ways and compares them pixel-by-pixel. A PASS means the GPU output matches the CPU reference within tolerance. A FAIL means the shader diverges for that configuration, and the stimulus will fall back to Canvas 2D rather than present a pattern it cannot vouch for.

Status: stimuli render on WebGL 2 by default, falling back to Canvas 2D on their own if the parity gate fails at session start. To force the CPU path for a recording, add &webgl=0 to a stimulus URL. This page runs the comparison on demand, so you can confirm a shader matches before you rely on it — and the renderer actually used is written into every log under renderer.

Test at your real recording settings. Parity depends on pattern geometry, screen size and gamma. Put the exact query string you use for recording into the box below (e.g. patternType=checker&screen_width_px=1920&…) and run each pattern type you use. The value maxDiff is the largest per-channel 8-bit difference; pctOver is the percentage of pixels above tolerance (default tolerance = 2 LSB).
